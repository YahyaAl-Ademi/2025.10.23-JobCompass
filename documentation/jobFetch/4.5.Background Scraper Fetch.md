### Overview

When an authenticated user performs a search for a string that is not fully cached, the system triggers a background task to scrape LinkedIn for the full search string. This provides more comprehensive results in subsequent searches.

```mermaid
sequenceDiagram
    autonumber
    %% File paths:
    %% JobController: server/src/controllers/jobData.js
    %% FetchPersister: server/src/services/fetchPersister.js
    %% ScraperFetch: server/src/services/linkedInScraperFetch.js
    %% Apify: Apify API (LinkedIn Jobs Scraper)
    %% PersistJobSearch: server/src/services/persistJobSearch.js
    %% ProcessScraperJob: server/src/util/processScraperJob.js
    %% NeonDB: Neon Database
    participant JobController as Job Search Controller<br/>jobData.js
    participant FetchPersister as Fetch Persister Service<br/>fetchPersister.js
    participant ScraperFetch as LinkedIn Scraper Service<br/>linkedInScraperFetch.js
    participant Apify as Apify API<br/>(LinkedIn Jobs Scraper)
    participant ProcessScraperJob as Scraper Job Normalizer<br/>processScraperJob.js
    participant PersistJobSearch as Persist Job Search Service<br/>persistJobSearch.js
    participant NeonDB as Neon Database

    Note over JobController,NeonDB: Phase 4.5: Background Scraper Fetch

    activate JobController
    Note over JobController: Full search_string NOT cached & user is authenticated
    JobController->>FetchPersister: call `fetchPersister(search_string, ...)`<br/>with `linkedInScraperFetch` as fetcher
    deactivate JobController

    activate FetchPersister
    FetchPersister->>ScraperFetch: call `linkedInScraperFetch(search_string)`
    activate ScraperFetch

    ScraperFetch->>Apify: POST /acts/.../runs (Start Scraper)
    Apify-->>ScraperFetch: Return runId

    loop Polling for Completion
        ScraperFetch->>Apify: GET /runs/[runId] (Check Status)
        Apify-->>ScraperFetch: Return status (RUNNING/SUCCEEDED)
    end

    ScraperFetch->>Apify: GET /dataset/items (Fetch Data)
    Apify-->>ScraperFetch: Return raw job data

    loop For each job in results
        ScraperFetch->>ProcessScraperJob: call `processScraperJob(job)`
        activate ProcessScraperJob
        Note over ProcessScraperJob: Normalize job fields
        ProcessScraperJob-->>ScraperFetch: Return normalized job
        deactivate ProcessScraperJob
    end

    ScraperFetch-->>FetchPersister: Return normalized jobs array
    deactivate ScraperFetch

    FetchPersister->>PersistJobSearch: call `persistJobSearch()`
    activate PersistJobSearch
    PersistJobSearch->>NeonDB: Upsert search_strings / jobs / search_strings_jobs
    deactivate PersistJobSearch
    deactivate FetchPersister
```

### Key Components

- **fetchPersister.js** (`server/src/services/fetchPersister.js`)
  - Handles the asynchronous execution of the fetcher.
  - Ensures the database connection is managed and results are persisted.
  - Deletes the search from `inProgressSearches` once completed.

- **linkedInScraperFetch.js** (`server/src/services/linkedInScraperFetch.js`)
  - Interacts with the Apify API to run the LinkedIn jobs scraper actor.
  - Polls for completion and retrieves the dataset.
  - Normalizes results using `processScraperJob.js`.

- **processScraperJob.js** (`server/src/util/processScraperJob.js`)
  - Normalizes the specific data format returned by the Apify scraper to match the application's internal job schema.

### Background Nature

This process is **non-blocking** for the main job search request. The `JobController` does not `await` the `fetchPersister` call. Instead, it proceeds to return the current (partially cached or RapidAPI-fetched) results to the user immediately. The scraper results will become available in the database for future searches once the background process completes (typically within 5-10 minutes).

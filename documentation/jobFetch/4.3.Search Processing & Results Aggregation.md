```mermaid
sequenceDiagram
    autonumber
    %% File paths:
    %% JobsContext: client/src/context/JobsContext.jsx
    %% useFetch: client/src/hooks/useFetch.js
    %% ExpressApp: server/src/app.js
    %% JobController: server/src/controllers/jobData.js
    %% CachedJobsService: server/src/services/getCachedJobsBySearchString.js
    %% RealJobSearch: server/src/controllers/rapidAPIfetch.js
    %% PersistSearchResults: server/src/services/persistSearchResults.js
    %% ProcessJobPost: server/src/util/processJobPost.js
    participant JobsContext as JobsContext Provider<br/>JobsContext.jsx
    participant useFetch_1 as useFetch Hook<br/>(jobs search)<br/>useFetch.js
    participant FrontendNetwork as HTTP Network Layer
    participant ExpressApp as Express Server<br/>app.js
    participant JobController as Job Search Controller<br/>jobData.js<br/>`searchJobs()`
    participant CachedJobsService as Cached Jobs Service<br/>getCachedJobsBySearchString.js
    participant NeonDB as Neon Database<br/>search_strings / jobs / search_strings_jobs
    participant RealJobSearch as Real Job Search Provider<br/>rapidAPIfetch.js
    participant RapidAPI as RapidAPI<br/>(LinkedIn Job Search)
    participant PersistSearchResults as Persist Search Results<br/>persistSearchResults.js
    participant ProcessJobPost as Job Normalizer<br/>processJobPost.js

    Note over JobsContext,ProcessJobPost: Phase 4.3: Search Processing & Results Aggregation
    activate JobController

    alt Valid search_string
        JobController->>CachedJobsService: Check cache for full `search_string`
        activate CachedJobsService
        CachedJobsService->>NeonDB: Query `search_strings` for full string
        activate NeonDB
        alt Full search_string cached
            NeonDB-->>CachedJobsService: Cached jobs found for full string
            deactivate NeonDB
            CachedJobsService-->>JobController: Return cached jobs
            deactivate CachedJobsService
            JobController->>ExpressApp: Return response with cached jobs
            deactivate JobController
            ExpressApp->>FrontendNetwork: HTTP 200<br/>{ success: true,<br/>  result: [job1, job2, ...] }
            FrontendNetwork->>useFetch_1: Response received
            useFetch_1->>useFetch_1: Parse JSON response
            useFetch_1->>useFetch_1: Set `isLoading = false`
            useFetch_1->>JobsContext: Call `handleJobFetchResults(data)`<br/>(callback function)
        else Not cached for full string
            JobController->>JobController: Split search terms into words:<br/>`searchWords = search_string.split(/[\\s\\-.'/]+/)`

        Note over JobController: Create concurrent fetch promises<br/>for all search words
        loop For each search word (index i)
            JobController->>CachedJobsService: call `getCachedJobsBySearchString()`<br/>Check if word is cached
            activate CachedJobsService
            CachedJobsService->>NeonDB: Query `search_strings` table
            activate NeonDB
            alt Word cached in DB
                NeonDB-->>CachedJobsService: Word found
                CachedJobsService->>NeonDB: Query `jobs` table via `search_strings_jobs`
                NeonDB-->>CachedJobsService: Return cached jobs
                deactivate NeonDB
                CachedJobsService-->>JobController: Return cached jobs array
                deactivate CachedJobsService
            else Word NOT cached
                CachedJobsService-->>JobController: No cached jobs
                JobController->>JobController: Fallback to real search
                alt i >= 2 AND searchWords.length > 2
                    Note over JobController: Apply throttling:<br/>setTimeout (i-1) * 700ms
                    JobController->>RealJobSearch: call `rapidAPIfetch(searchWord)`
                else
                    JobController->>RealJobSearch: call `rapidAPIfetch(searchWord)` (immediate)
                end
                activate RealJobSearch
                RealJobSearch->>RapidAPI: GET LinkedIn Job Search API
                RapidAPI-->>RealJobSearch: Return raw job data

                Note over RealJobSearch: Call persistSearchResults()<br/>service to normalize and save
                RealJobSearch->>PersistSearchResults: call `persistSearchResults()`<br/>with aggregated jobs
                activate PersistSearchResults
                PersistSearchResults->>NeonDB: Insert/update search_strings table<br/>for searchWord (and full search_string)
                loop For each job in aggregated results
                    PersistSearchResults->>ProcessJobPost: call `processJobPost(job)`
                    activate ProcessJobPost
                    ProcessJobPost->>ProcessJobPost: Normalize job fields:<br/>- Parse & clean description<br/>- Extract & format location<br/>- Add computed fields
                    ProcessJobPost-->>PersistSearchResults: Return normalized job
                    deactivate ProcessJobPost
                    PersistSearchResults->>NeonDB: Insert job if not exists<br/>Link in search_strings_jobs
                end
                PersistSearchResults-->>RealJobSearch: Return normalized jobs array
                deactivate PersistSearchResults

                RealJobSearch-->>JobController: Return normalized jobs array
                deactivate RealJobSearch
            end
        end
            JobController->>JobController: `await Promise.all(fetchPromises)` to aggregate results

            JobController->>JobController: Aggregate results from all words<br/>Remove duplicates using Set of job IDs<br/>Maintain insertion order

            Note over JobController: Jobs are already normalized<br/>by persistSearchResults service<br/>called within rapidAPIfetch

            JobController->>ExpressApp: Return response with<br/>aggregated, normalized jobs
            ExpressApp->>FrontendNetwork: HTTP 200<br/>{ success: true,<br/>  result: [job1, job2, ...] }
            FrontendNetwork->>useFetch_1: Response received
            useFetch_1->>useFetch_1: Parse JSON response
            useFetch_1->>useFetch_1: Set `isLoading = false`
            useFetch_1->>JobsContext: Call `handleJobFetchResults(data)`<br/>(callback function)
        end
    end
```
